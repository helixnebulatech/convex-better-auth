title: Migrate to 0.14
description: Migrate to @convex-dev/better-auth@0.14
---

0.14 needs Better Auth 1.7.25 or later in the `1.7.x` line. It has no breaking
API changes: the component functions, the schema and the options stay the same.
It's a minor release because the Better Auth floor goes up and because routes
with `cors` now expose more headers.

## Upgrade

Upgrade the component, Better Auth and every `@better-auth/*` package you use,
such as `@better-auth/expo` or `@better-auth/oauth-provider`, in one command, so
the package manager doesn't reject the new peer range against the old Better
Auth:

```npm
npm install @convex-dev/better-auth@npm:@helixnebulatech/convex-better-auth@^0.14.0 better-auth@~1.7.25
```

With Local Install, the schema generated with Better Auth 1.7.25 is the same as
with 1.7.18, so there's nothing to regenerate.

## CORS exposed headers

With `registerRoutes(http, createAuth, { cors })` or `registerRoutesLazy`, the
routes now keep the `Access-Control-Expose-Headers` Better Auth sets and add
`Set-Better-Auth-Cookie` and `cors.exposedHeaders` to it. Before, the CORS
router replaced that list, so cross-origin clients couldn't read headers Better
Auth exposes itself:

- `WWW-Authenticate` on `oauthProvider` 401 challenges
- `set-auth-token` from `bearer`
- `set-auth-jwt` from `jwt`
- `set-ott` from `oneTimeToken`

If you added any of these to `cors.exposedHeaders` to work around it, you can
remove them. If you serve Better Auth through your own CORS layer, such as
Hono's `cors` middleware, add them to its exposed list. See
[CORS exposed headers](/security#cors-exposed-headers).

## Changes in Better Auth 1.7.19 to 1.7.25

These Better Auth changes can affect Convex apps. Read the
[Better Auth changelog](https://better-auth.com/changelog) for the full list.

- **Email verification:** an error thrown from `sendVerificationEmail` no longer
  rejects the sign-up. It's logged and the sign-up succeeds. Reject sign-ups in
  a `databaseHooks.user.create.before` hook instead (1.7.21).
- **Revoking sessions:** `revokeSession`, `revokeSessions` and
  `deleteUser({ token })` expire the session cookie when they revoke the current
  session. The component clears the Convex JWT cookie with it, as on sign-out
  (1.7.22).
- **Adapter `update`:** Better Auth now expects `update` to change one row and
  `updateMany` to change every match. The component already worked this way
  (1.7.21).
- **SCIM:** on adapters without native transactions, such as Convex, the SCIM
  plugin no longer fails at startup, and `/scim/v2` requests return 501. It
  still can't provision users and groups on Convex (1.7.21).
- **OAuth provider:**
  - Rejected `post_logout_redirect_uris` return `invalid_redirect_uri` instead
    of `invalid_client_metadata` (1.7.21).
  - Discovery and the `iss` parameter no longer rewrite an `http` issuer to
    `https`, so set `baseURL` to the public `https` URL (1.7.20).
  - `oauthProviderResourceClient(auth)` reads signing keys from the auth
    instance; set `jwksUrl` to keep fetching them over HTTP (1.7.25).
- **Passkey:** with a wildcard in `baseURL.allowedHosts` covering your `rpID`
  and no `origin`, return tenant origins from a `trustedOrigins` function
  (1.7.21).
- **DPoP:** if you accept DPoP-bound tokens in your own HTTP actions, call
  `enforceDpopBinding` from `better-auth/oauth2` with a shared replay store
  (1.7.24).

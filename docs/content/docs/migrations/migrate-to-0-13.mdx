## Breaking changes

<div className="fd-steps">

  <div className="fd-step">

### Use `signIn.social` for Generic OAuth providers

Better Auth 1.7 registers each Generic OAuth provider as a social provider.
Remove `genericOAuthClient()` from your auth client, and use `signIn.social`
instead of `signIn.oauth2`.

```ts
export const authClient = createAuthClient({
  plugins: [
    genericOAuthClient(), // [!code --]
    convexClient(),
  ],
});

await authClient.signIn.oauth2({ providerId: "slack" }); // [!code --]
await authClient.signIn.social({ provider: "slack" }); // [!code ++]
```

The callback URL changes from `/api/auth/oauth2/callback/<providerId>` to
`/api/auth/callback/<providerId>`. Update the redirect URL in the settings of
each OAuth provider.

  </div>

  <div className="fd-step">

### OIDC Provider tables are removed from the default schema

Better Auth 1.7 removes the deprecated `oidcProvider` plugin. The default
component schema no longer has the `oauthApplication`, `oauthAccessToken` and
`oauthConsent` tables.

If your app does not use the OIDC Provider plugin, you do not have to do
anything.

If your app uses it, move to
[`@better-auth/oauth-provider`](https://www.better-auth.com/docs/plugins/oauth-provider)
with [Local Install](/local-install). The deploy does not delete documents that
are in the old tables.

  </div>

  <div className="fd-step">

### Move `experimental.joins` to `advanced.database.joins`

If you set `experimental: { joins: true }`, change it to
`advanced: { database: { joins: true } }`. The Convex adapter does not support
joins yet, so it continues to set this option to `false`.

  </div>

  <div className="fd-step">

### Review breaking changes in Better Auth 1.7

Be sure to review the
[Better Auth 1.7 release post](https://better-auth.com/blog/1-7) for other
breaking changes that can have an effect on your app. For example,
`twoFactor.enable` now returns a `method` field. Check that `method` is `"totp"`
before you read `totpURI` and `backupCodes`.

  </div>

</div>

## Upgrading to 0.13.2

0.13.2 adds indexes to the component schema. Apps using the default install get
them on their next deploy. Apps using [Local Install](/local-install) need to
regenerate their schema and deploy to get them:

- `rateLimit.lastRequest`, used when Better Auth deletes expired rate limit
  rows.
- Indexes for the unique constraints Better Auth declares at the table level,
  such as `deviceCode` and `userCode` for the device authorization plugin.

```npm
cd convex/betterAuth
npx auth generate
```

Without the new indexes everything keeps working, but these queries scan the
whole table, and unique checks without an index log a warning asking you to
regenerate the schema.

## Upgrading to 0.13.3

0.13.3 includes security fixes. See the [security notes](/security) for how the
component behaves now.

### Cross domain apps

With the cross domain plugin, OAuth sign-in now goes through your Convex site
before the provider, so it's tied to the browser that started it, as it is with
Better Auth on a single domain.

- Deploy your Convex backend and your frontend together. An old client can't
  complete an OAuth sign-in against the new server, and the other way round.
  Users with the app already open need to reload it before signing in with an
  OAuth provider. Email, magic link, OTP and existing sessions aren't affected.
- If you call `signIn.social` or `linkSocial` with `disableRedirect: true`,
  start the redirect with `authClient.startOAuthRedirect(data.url)` instead of
  opening the URL yourself.
- The session is only handed to your app at `siteUrl`. Callback URLs on other
  origins, even trusted ones, are redirected to without a session.

### JWT caching

If you use `jwtCache`, `isAuthenticated()` now checks the session with the
server on every call, like Better Auth's `getSession`. Other server helpers
still reuse the cached JWT, after verifying its signature. If the
`convexSiteUrl` you pass differs from `CONVEX_SITE_URL` in your deployment, set
`jwtCache.issuer` so the cached JWT can be verified.

### Queries on null fields

`lt`, `lte`, `gt`, `gte`, `ne` and `not_in` where clauses no longer match
documents where the field is null or unset, as with Better Auth's SQL adapters.
Check your own queries through the component adapter if they relied on that.
